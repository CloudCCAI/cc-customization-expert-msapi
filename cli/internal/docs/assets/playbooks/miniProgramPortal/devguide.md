# 小程序与客户门户设计指南

## 设计顺序

1. 身份入口：微信授权、手机号、验证码、企业认证。
2. 账号映射：微信用户、联系人、客户、用户账号之间的关系。
3. 权限控制：未登录、未认证、已认证、已绑定设备的可见功能。
4. 业务入口：服务申请、保养预约、设备列表、订单查询、客服。
5. 通知机制：状态变更、受理、派工、完成、评价。
6. 接口设计：登录、注册、查询、新建、上传、评价。
7. 后台配置：轮播图、产品分类、推荐内容、公告。

## 状态控制

```text
未登录：
- 允许浏览公开内容。
- 业务入口提示登录。

已登录未认证：
- 可查看基本信息。
- 服务申请、设备绑定等入口提示认证。

已认证：
- 可绑定设备。
- 可提交服务请求。
- 可查看个人相关服务进度。

已绑定设备：
- 可查看设备详情、保修、工况和服务历史。
```

## 通知设计

常见通知触发点：

- 服务请求提交成功。
- 服务请求已受理。
- 已派工。
- 工程师出发或到达。
- 工单完成。
- 待评价。

建议：

- 通知权限授权要在前端交互中设计。
- 状态变更和通知发送要解耦。
- 通知失败不应影响主流程。

## 安全建议

- 不要在小程序前端保存外部系统密钥。
- 设备绑定必须校验设备编号和客户关系。
- 文件上传要限制大小、类型和关联对象。
- 查询接口必须按当前用户过滤数据。
- 涉及手机号、位置、设备信息时要按项目安全要求处理。
