# 售后服务工单设计指南

## 状态机建议

```text
服务请求：
已提交 -> 已受理 -> 进行中 -> 已完成 -> 已评价

服务工单：
待指派 -> 已分配 -> 已派遣 -> 进行中 -> 已完成 -> 已关闭

异常状态：
已退单 / 已取消 / 服务中断 / 厂端支持中 / 待配件 / 待回访
```

实际状态需按项目角色、审批和移动端体验确认。

## 调度设计

### 自动派工

适合：

- 资产已经绑定服务网点和服务工程师。
- 设备不跨区。
- 工单类型和技能要求明确。

设计点：

- 资产服务归属。
- 服务网点覆盖区域。
- 工程师可用性。
- 工单类型和技能匹配。
- 派工失败兜底人。

### 人工派工

适合：

- 未绑定工程师。
- 设备跨区。
- 工单类型复杂。
- 需要厂端协调。
- 自动规则无法判断。

## 现场执行

APP 或移动端常见动作：

- 接单。
- 出发。
- 到达。
- 开始工作。
- 服务中断。
- 二次出发和二次到达。
- 结束工作。
- 上传照片和附件。
- 填写服务工作记录。
- 提交技术支持申请。
- 发起配件申请。
- 提交完工。

设计时应确认：

- 是否记录经纬度。
- 是否计算里程。
- 是否限制重复出发。
- 是否要求拍照模板。
- 是否需要离线保存。
- 是否需要客户签字。

## 工单生成规则

### 销售交付触发

销售订单、合同或交货完成后，可按资产和业务类型生成交机、预验收或其他服务工单。

建议：

- 触发器只写待生成标记或创建轻量记录。
- 复杂规则放到类或 sidecar。
- 保留来源单据和来源明细编号。

### 周期策略触发

适合点检、保养、防锈运转、巡检等周期任务。

建议：

- 策略单独配置。
- 记录上次生成时间。
- 防止重复生成。
- 支持人工补生成。

### 车联网触发

适合根据工作小时、故障码、位置等外部数据生成工单或提醒。

建议：

- sidecar 拉取和清洗车联网数据。
- 使用故障编号、设备编号和未完工状态查重。
- 生成工单前先判断资产、服务商、跨区和派工规则。

## 跨区服务

设计点：

- 服务区域口径，如城市、网点、代理商授权区域。
- 位置来源和可信度。
- 跨区提醒。
- 跨区申请。
- 审批通过后的资产服务归属变更。
- 跨区时是否禁止自动派工。

## 索赔和结算

索赔常见依据：

- 工单类型。
- 保内/保外。
- 维修作业。
- 配件更换。
- 里程。
- 工时。
- 旧件处理。
- 技术报告。

结算常见方式：

- 多个工单按周期汇总结算。
- 代理商确认。
- 厂端审核。
- 与财务或 QMS 系统同步。

建议将索赔、结算设计成独立对象，避免把费用规则直接写死在工单对象里。

## 报表看板

- 服务请求响应时间。
- 工单派工及时率。
- 到达及时率。
- 完工及时率。
- 一次修复率。
- 客户满意度。
- 配件消耗。
- 索赔金额。
- 结算金额。
- 区域设备健康趋势。
