# 制造业营销服一体化设计指南

## 建模顺序

1. 定义组织层级：集团、业务单元、区域、代理商、服务网点。
2. 定义主数据：客户、联系人、产品、物料、资产、服务商、工程师。
3. 定义交易主线：线索、商机、报价、合同、订单、交货、开票、回款。
4. 定义服务主线：服务请求、服务工单、执行记录、索赔、结算、评价。
5. 定义集成边界：ERP、BPM、MDM、资金、车联网、小程序等。
6. 定义报表看板：漏斗、赢单率、合同履约、订单交付、回款、服务及时率。

## 典型对象组合

```text
客户 -> 联系人
客户 -> 商机 -> 报价 -> 合同 -> 订单 -> 交货 -> 开票 -> 回款
客户 -> 资产 -> 服务请求 -> 服务工单 -> 服务执行记录 -> 索赔/结算 -> 评价
代理商 -> 服务网点 -> 服务工程师 -> 服务工单
产品/物料 -> 订单明细 / 配件更换 / 资产型号
```

## 实施建议

- 对象模型要同时支持销售和售后，不要让资产只服务单一流程。
- 代理商、服务网点、服务工程师是派工和结算的基础数据，必须尽早治理。
- 合同、订单、开票、回款要清晰区分单据状态和同步状态。
- 服务工单应沉淀现场执行数据，支撑索赔、结算和质量分析。
- 小程序入口需要先解决身份、设备绑定和权限。
- 车联网类接口通常适合 sidecar 承载轮询、清洗和规则生成。

## 常见待确认

- 产品线差异。
- 组织层级和数据权限。
- 主数据唯一编码来源。
- 合同和订单是否以 ERP 为主。
- 审批系统是否返回状态和单号。
- 车联网数据质量和延迟。
- 服务费用和索赔规则。
- 移动端是否需要离线能力。
