# CloudCC 多系统集成设计指南

## 决策表

| 问题 | 倾向 |
|---|---|
| 是否必须阻塞用户保存？ | 是：触发器/类；否：sidecar |
| 是否需要用户即时看到结果？ | 是：按钮/类；否：sidecar |
| 外部 API 是否短耗时且稳定？ | 是：类/按钮可接受；否：sidecar |
| 是否有批量、分页、长任务？ | 是：sidecar |
| 是否需要失败重试和补偿？ | 是：sidecar |
| 是否需要接收外部回调？ | 是：sidecar |
| 是否要跨多个外部系统编排？ | 是：sidecar |
| 是否只是 CloudCC 内部轻量逻辑复用？ | 是：类 |
| 是否由记录保存事件触发？ | 可用触发器，但复杂外呼建议只写待同步状态，由 sidecar 处理 |

## 什么时候用按钮

使用按钮的条件：

- 用户明确发起操作
- 用户需要立即看到结果
- 外部 API 短耗时、稳定
- 失败可以直接提示用户
- 不需要复杂重试

示例：

```text
客户详情页点击“查询工商信息”
  -> 类调用外部 API
  -> 返回数据
  -> 用户确认后写入字段
```

## 什么时候用类

使用类的条件：

- 逻辑需要在服务端执行
- 需要被按钮、组件、触发器复用
- 外部调用不适合暴露在前端
- 逻辑耗时可控

建议：

- 类负责封装业务语义，不要只做透明 HTTP 转发。
- 类调用外部 API 时，要处理错误并返回可理解的信息。
- 敏感凭据不要写在前端组件或客户端脚本中。

## 什么时候用触发器

使用触发器的条件：

- 逻辑和记录保存事件强绑定
- 必须在保存前或保存后执行
- 执行时间短
- 失败策略清晰

适合：

- 保存前字段校验
- 保存后生成关联记录
- 状态变化时写入同步标记

不适合：

- 慢接口调用
- 大批量同步
- 多系统编排
- 需要复杂重试补偿的集成

推荐写法：

```text
触发器只捕获业务事件和写入状态：
- sync_status = Pending
- sync_request_id = 唯一请求号
- sync_error = 空
```

## 什么时候用定时类

使用定时类的条件：

- 周期性执行
- 数据范围可控
- 不依赖用户即时反馈
- 可在 CloudCC 平台运行时内完成

适合：

- 周期性提醒
- 轻量数据同步
- 数据回填
- 失败记录重扫

如果同步链路复杂或数据量大，建议改为 sidecar。

## 什么时候用 sidecar

使用 sidecar 的条件：

- 外部接口慢或不稳定
- 需要队列、重试、补偿、死信
- 需要接收 Webhook
- 需要多系统编排
- 需要复杂数据映射
- 需要独立日志和监控
- 需要隔离密钥、证书、网络连接
- 需要用非 CloudCC 平台运行时能力

建议 sidecar 至少具备：

- 幂等键：如 `sync_request_id` 或业务唯一键
- 状态机：Pending、Processing、Success、Failed、Canceled
- 重试计数和下次重试时间
- 错误信息和外部响应摘要
- 人工重放或重试入口
- 集成日志

## 推荐字段设计

复杂集成建议在业务对象或集成日志对象上维护：

```text
sync_status
sync_request_id
external_id
last_sync_time
retry_count
next_retry_time
sync_error_message
sync_payload_hash
```

字段名称仅为方法论建议，实际 API 名需按项目命名规范确认。

## 反模式

不要：

- 在触发器中直接调用慢接口导致用户保存卡住。
- 在触发器中做大批量外部同步。
- 没有幂等键就调用外部创建接口。
- 把外部系统密钥写在前端组件或客户端脚本里。
- 由前端直接调用敏感外部接口。
- 没有同步日志，只靠用户反馈排查失败。
- 让 sidecar 和 CloudCC 同时无约束修改同一批字段。

## 真实项目抽象示例

以下示例来自制造业营销服一体化项目的抽象，不包含客户专有信息。

### 外部审批提交

```text
用户点击“提交审批”
  -> CloudCC 按钮打开确认交互
  -> 类校验当前记录状态和必填字段
  -> sidecar 或外部 API 创建审批流程
  -> 回写 sync_status、external_id、external_status
```

适合合同评审、交货审批、调拨审批、变更审批等场景。

### 电子签章

```text
用户点击“发起签署”
  -> 类组装合同和签署人信息
  -> sidecar 调用电子签平台
  -> 记录签署流程 ID
  -> sidecar 接收签署完成回调
  -> 回写签署状态并归档附件
```

电子签章通常涉及模板、文件、回调和附件归档，推荐使用 sidecar 承载长链路。

### 资金流水接收

```text
资金系统推送流水
  -> sidecar 接收和校验
  -> 按客户、单号或业务键匹配 CloudCC 数据
  -> 创建流水记录或异常记录
  -> 由 CloudCC 触发器汇总剩余可认领金额
```

资金流水不宜直接进入触发器长链路，应保留异常处理和人工认领入口。

### 车联网故障工单

```text
sidecar 定时拉取故障或工况
  -> 清洗设备编号、故障码、工作小时
  -> 按未完成工单查重
  -> 创建服务请求或服务工单
  -> CloudCC 自动派工或转人工派工
```

车联网数据通常存在延迟、重复和质量问题，推荐在 sidecar 中做清洗、查重和规则判断。

## 待确认

当前技能未规定 sidecar 的具体技术栈、部署方式、队列组件或数据库。涉及这些内容时，应根据客户基础设施和安全要求单独设计。
