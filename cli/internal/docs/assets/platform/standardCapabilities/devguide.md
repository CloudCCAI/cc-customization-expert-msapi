# CloudCC 标准能力复用设计指南

## 必读顺序

任何业务蓝图、全局建模、模块设计或对象字段方案前，Agent 必须先读取：

```bash
cloudcc doc platform/standardCapabilities introduction
cloudcc doc platform/capabilityMap introduction
cloudcc doc platform/object introduction
cloudcc doc platform/fields introduction
```

若目标租户可连接，再执行：

```bash
cloudcc scan msapi <projectPath> standard-catalog
```

读取扫描结果时必须同时看：

- `objects`：租户对象全集，每个对象包含字段级 `fields`、动态 `inferredRole`、引用字段 `referenceFields` 和 `capabilitySignals`。
- `capabilityObjects`：标准能力对象覆盖清单，包含预置核心能力命中项和动态发现项。动态发现项状态为 `discovered`，用于捕获业务机会小组、客户小组、联系人角色、业务机会产品等无菜单入口或容易漏掉的对象。

`tp_sys_object.TABLE_TYPE = '2'` 的对象必须全部视为标准业务数据对象。读取结果时先看 `objects[].tableType` 和 `objects[].standardBusinessObject`，再看动态推断角色。不能把 `TABLE_TYPE = '2'` 的联系方式、业务机会小组等对象排除在标准能力复用判断之外。

## 标准能力匹配步骤

1. 识别业务域：CRM、商务云、CPQ、现场服务云、客户服务云、项目云、伙伴云、利润云或其他行业云。
2. 查找标准应用：目标租户是否已有对应应用和菜单。
3. 查找标准对象：是否已有语义匹配的标准对象，包含没有菜单入口的关系对象和明细对象。
4. 查找标准字段：是否已有同义字段、状态字段、金额字段、时间字段、外部编号字段、关联字段和数量/价格/折扣字段。
5. 判断扩展方式：字段扩展、记录类型、页面布局、验证规则、审批过程、权限或共享规则。
6. 判断是否新建：只有标准能力无法承载时才新建对象。


## 复用矩阵模板

```text
| 业务能力 | 标准应用 | 标准对象/能力 | 复用方式 | 扩展字段/规则 | 自定义缺口 | 证据 |
|---|---|---|---|---|---|---|
```

复用方式建议：

| 复用方式 | 含义 |
|---|---|
| reuse | 直接复用标准对象和字段 |
| extend | 复用标准对象，扩展字段、记录类型、布局或规则 |
| bridge | 使用中间关系对象连接标准对象和客户特有维度 |
| mirror | 外部系统是主事实，CloudCC 只做只读镜像 |
| custom | 标准能力无法承载，创建自定义对象 |

## 典型判断

### 客户小组

当需求描述为“同一个客户由多个销售、技术、客服、财务协同服务”时，优先复用标准客户小组/客户团队和共享规则。

只有在客户小组无法表达以下内容时，才考虑新增客户经营归属类对象：

- 同一客户在不同业务线下有不同负责人。
- 同一客户在不同区域有不同经营状态。
- 目标、返利、价格、订单归属必须按业务线/区域独立统计。
- 客户小组只解决共享权限，不承载经营口径。

### 业务机会小组

当需求描述为“一个业务机会由多个销售、售前、产品、交付或渠道成员协同推进”时，优先复用业务机会小组/商机团队类标准对象，例如 OpportunityTeam。扫描不能依赖菜单入口，必须通过对象全集、字段引用和 Team/小组/团队命名动态发现。

必须扫描字段级，确认业务机会、成员、角色、访问权限等字段是否存在。只有当标准业务机会小组无法表达客户特有经营归属、目标拆分、跨业务线独立核算或外部团队主数据时，才考虑扩展字段或新增桥接对象。

### 联系人角色

当需求描述为“同一联系人在客户、商机、项目或采购链路中承担不同角色”时，优先复用联系人角色类标准对象，例如 ContactRole、AccountContactRole 或 OpportunityContactRole。必须扫描到字段级，确认客户/商机、联系人、角色、是否主要联系人等字段是否存在。

只有在标准联系人角色无法表达客户专属角色体系、角色生效周期、外部主数据编号或跨业务线角色口径时，才考虑扩展字段或新增桥接对象。

### 联系方式

当需求描述为“客户、联系人、线索有多个电话、手机、邮箱、微信、地址或默认联系方式”时，优先复用 `TABLE_TYPE = '2'` 的联系方式/ContactPoint/ContactMethod 类标准业务对象。必须扫描字段级，确认客户/联系人/线索引用、电话、手机、邮箱、类型、用途、是否默认等字段。

如果联系方式对象存在但字段不足，优先扩展标准对象字段和页面布局；只有外部系统是联系方式主事实且 CloudCC 只做镜像时，才考虑镜像对象。

### 业务机会产品

当需求描述为“商机下关联产品、数量、价格、折扣、金额、预测收入或产品方案”时，优先复用业务机会产品类标准对象，例如 OpportunityProduct 或 OpportunityLineItem。必须扫描字段级，确认业务机会、产品、数量、销售价格、折扣、小计等字段是否存在。

只有当产品明细生命周期不属于商机、价格事实完全由外部系统主控，或客户要求的明细结构无法由标准对象扩展时，才考虑镜像对象或自定义对象。

### CPQ 和价格

当需求描述为“产品配置、报价、价格规则、折扣和报价审批”时，优先复用 CPQ 能力。只有在项目只是同步外部价格事实、或客户定价生命周期与 CPQ 报价生命周期完全不同，才使用自定义价格政策或价格报批对象。

CPQ/商务云必须同时检查价格表条目、报价产品和订单产品等明细对象，并在扫描结果里保留字段级证据。不能只检查 Quote、Order、Product 主对象。

### 客诉和服务

当需求描述为“客户投诉、服务请求、SLA、知识库、处理闭环”时，优先复用客户服务云 Case/服务工单能力。只有当客户服务云未启用，或客诉需要行业专属质量责任、赔付和整改闭环且标准工单无法扩展时，才新建客诉对象。

### 伙伴门户

当需求描述为“客户/伙伴登录门户、查看订单、提交服务请求、管理外部账号”时，优先复用伙伴云、门户应用、外部用户、角色和共享规则。自定义门户账号对象通常只做账号绑定审计或外部系统镜像，不应替代标准外部用户。

### 利润和成本

当需求描述为“毛利、预算、成本、利润中心、盈利分析”时，优先检查利润云。若利润云未启用或成本主事实在 ERP/NCC，CloudCC 可采用镜像快照对象承载报表口径，但必须标明外部系统主责。

## 反模式

- 没有阅读标准能力目录就设计自定义对象。
- 把客户小组、联系人角色、业务机会产品、报价产品、订单产品、工单、项目、伙伴门户、利润分析等标准能力重建成同义自定义对象。
- 因为字段不够就新建对象，而不是先扩展标准对象。
- 未扫描目标租户就断言某个标准对象不存在。
- 只扫描主对象或菜单对象，漏掉无菜单入口的关系对象、团队对象和明细对象。
- 只依赖预置标准对象清单，用户指出一个对象才补一个对象，而不是先把 `TABLE_TYPE = '2'` 的标准业务对象全集和字段全集扫出来。
- 把外部系统主事实当成 CloudCC 内部主控对象，导致集成和报表口径冲突。
