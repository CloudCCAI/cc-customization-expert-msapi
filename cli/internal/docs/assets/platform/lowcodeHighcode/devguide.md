# CloudCC 低代码 + 高代码实施指南

## 实施路径

### 1. 配置优先

先完成：

- 对象
- 字段
- 页面布局
- 应用和菜单
- 简档和权限
- 基础验证规则

### 2. 自动化增强

再评估：

- 工作流
- 批准过程
- 动作
- 查重过滤器

### 3. 代码扩展

当配置不足时再添加：

- 客户端脚本
- 类
- 触发器
- 定时类
- pagecomponent
- sidecar

## 升级到高代码的判断

需要高代码的信号：

- 规则跨多个对象且不可配置
- 页面交互有复杂组件或实时可视化
- 需要调用外部 API
- 需要复杂数据转换
- 需要周期性后台处理
- 需要独立前端构建和发布

不建议高代码的情况：

- 只是字段必填或简单条件校验
- 只是调整字段显示顺序
- 只是不同角色看到不同字段
- 只是简单通知或字段更新

## 目录约定

当前 Go 技能生成的项目目录：

```text
frontend/    前端页面组件及相关构建文件
backend/     classes、triggers、schedule 等后端代码
sidecar/     外挂中间程序
根目录        cloudcc-cli.config.json 等全局配置
```

## 交付建议

以下为通用工程实践：

- 每个需求先写能力路径，再写实现命令。
- 高代码文件要与平台配置对应，避免只有代码没有元数据说明。
- 触发器和定时类要记录影响对象、触发时机、失败处理。
- pagecomponent 要记录挂载页面、依赖静态资源和后端类。
- sidecar 要记录部署方式、环境变量、凭据来源和日志位置。
