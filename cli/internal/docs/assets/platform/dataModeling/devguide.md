# CloudCC 数据建模设计指南

## 建模步骤

### 1. 识别业务实体

优先确认是否已有标准对象可承载。只有标准对象无法表达业务语义时，才创建自定义对象。

### 2. 定义对象边界

一个对象应代表一个稳定的业务实体，而不是一个临时页面或报表。

建议确认：

- 记录的生命周期
- 记录所有人
- 主要状态字段
- 是否允许报表
- 是否需要快速创建
- 是否需要定位服务

### 3. 选择字段类型

根据数据语义选择字段类型，不要全部用文本字段。

常见选择：

- 状态、类型、阶段：选项列表或全局选项列表
- 金额：币种
- 比例：百分比
- 关联客户/联系人/项目：查找关系
- 强父子关系：主详关系
- 系统编号：自动编号
- 计算值：公式或累计汇总
- 是否类字段：复选框

### 4. 设计关系

查找关系适合弱关联；主详关系适合强从属关系。

使用主详关系前必须确认：

- 子记录是否必须依赖父记录
- 父记录删除时是否允许影响子记录
- 子记录权限是否应由父对象决定
- 是否需要累计汇总

### 5. 设计数据质量

先用字段类型和必填控制，再使用：

- 字段依赖
- 验证规则
- 查重过滤器
- 触发器

### 6. 设计页面和移动端

页面布局不只是展示问题，它会影响用户录入路径和移动端体验。

至少确认：

- PC 详情页布局
- 行式布局
- 悬停布局
- 移动端布局
- 简档布局分配

## 行业通用建议

以下为通用建模经验：

- 对象名和 API 名要稳定，避免频繁变更。
- 状态字段要少而清晰，避免把多个流程状态混在一个字段里。
- 对外集成字段要单独命名并记录来源系统。
- 报表口径字段要优先标准化，不要让每个报表自行计算。
- 大文本字段不适合承载需要筛选、统计和权限控制的结构化数据。

## Agent 输出清单

给出建模方案时，应包含：

- 对象清单
- 字段清单和字段类型
- 关系设计
- 页面布局建议
- 权限影响
- 自动化影响
- 数据导入/迁移影响
- 待确认问题
