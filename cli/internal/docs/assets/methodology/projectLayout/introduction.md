# CloudCC 项目目录规范

用于项目初始化、存量目录审计、目录扩展登记和前端源码归属检查。先运行 `cloudcc doctor project-layout <projectPath>` 获取只读清单，再按项目 AGENTS、白名单和实际交付范围决定是否采用登记文件。

- 固定入口：项目说明、治理状态、规格、交付索引、参考资料索引。
- 按需能力目录：后端、前端（含客户端脚本）、sidecar、平台页面及静态资源。
- 可登记扩展：项目工具、部署资源、专属技能和外部工具入口。
- 本地内容：连接配置、缓存、截图工作区；必须与共享源码和正式证据分开。
- 历史材料：保留来源、替代关系和引用，不自动移除或伪造审批。

`doctor project-layout` 离线运行，不读取租户凭据、不访问网络、不改动文件。没有登记文件时，未知目录是待分类建议；显式登记后，未登记一级路径构成错误。它不证明业务验收成功，也不替代其他项目治理、交付物和测试契约检查。

完整目录树包含每个目录的职责和【必】、【阶段】、【按需】、【本地】创建条件，并说明规范要求与初始化、目录检查实际行为的边界。完整命令、目录职责、登记结构和源码路径规则见 `cloudcc doc projectLayout devguide`。
