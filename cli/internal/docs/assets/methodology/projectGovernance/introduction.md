# CloudCC 项目标准治理

## 定位

本模块用于治理 CloudCC 实施项目中跨模块、跨阶段长期生效的方法、表达、文档、命名和评审标准。

它解决三类常见问题：

- 长篇项目规范散落在仓库根目录，后续代理无法稳定发现。
- `AGENTS.md` 复制整套规范，入口规则与正文逐渐漂移。
- 标准文档重复维护业务范围、系统边界、对象字段或排期，形成多个事实源。

核心原则：

```text
AGENTS.md 负责强制读取入口
00-governance/standards 负责项目标准正文
FEAT、蓝图、ADR、DevOps 负责可追溯事实
.claw 负责动态状态和任务
```

项目标准只说明“应该怎样做、怎样表达、怎样评审”，不独立决定“当前业务实际是什么”。

## 何时读取

- 初始化或治理 `docs/delivery/<project-code>/`。
- 创建、迁移或废止跨模块长期规范。
- 创建、修改或评审业务流程图、系统流程图或长期文档模板。
- 发现根目录存在长篇项目规范，或同一事实被多个文档重复维护。

详细目录、元数据、索引、读取门禁和归档规则见：

```bash
cloudcc doc methodology/projectGovernance devguide
```
