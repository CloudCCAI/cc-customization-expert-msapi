## 设计判断规则

### 何时使用标准对象

模块设计前必须先运行或引用 `cloudcc scan msapi <projectPath> standard-catalog` 的结果。优先使用 CloudCC 已有语义明确的标准应用、标准对象和标准字段承载业务场景，例如 CRM 全流程对象、商务云、CPQ、现场服务云、客户服务云、项目云、伙伴云、利润云中已经启用的能力。只有当业务语义、生命周期、字段结构、权限边界或集成事实归属明显不同，才设计自定义对象。

标准对象复用判断必须写清楚：

```text
目标租户是否已扫描：
命中的标准应用：
命中的标准对象：
命中的标准字段：
需要扩展的标准字段：
不能复用的原因：
```

常见优先复用点：

| 业务域 | 优先检查 |
|---|---|
| 客户协同 | Account、Contact、客户小组/客户团队、共享规则 |
| 线索商机 | Lead、Opportunity、Campaign、活动/任务 |
| 报价和价格 | CPQ、产品、价格本、报价、订单 |
| 合同和订单 | 合同、订单、订单明细、产品、价格 |
| 客户服务 | 客户服务云、Case/服务工单、知识库、满意度 |
| 现场服务 | 现场服务云、工单、派工、服务资源、现场执行 |
| 项目交付 | 项目云、项目、里程碑、任务、工时和成本 |
| 伙伴门户 | 伙伴云、外部用户、门户应用、共享规则 |
| 利润和预算 | 利润云、预算、成本、利润分析 |

### 何时使用记录类型

同一个对象有相似生命周期，但字段、页面、阶段、审批或规则因业务类型不同而变化时，优先考虑记录类型。例如直销、渠道、融资租赁、全款、分期等业务分类。

### 何时设计相关列表

当主记录需要承载明细、历史、附件、审批记录、接口日志、费用明细、服务记录时，应通过相关列表表达从属关系，避免把多行明细塞进一个长文本字段。

### 何时设计触发器

适合：

- 编号生成。
- 汇总明细金额。
- 状态回写。
- 同步标记。
- 保存前后强一致校验。

不适合：

- 慢接口调用。
- 批量长任务。
- 多系统编排。
- 需要复杂重试补偿的逻辑。

### 何时设计按钮和类

适合：

- 用户明确发起动作。
- 需要二次确认。
- 提交外部审批。
- 查询库存、信用、物流等即时结果。
- 触发电子签、同步 SAP、推送资金系统等操作。

按钮负责交互入口，类负责服务端业务逻辑，复杂链路交给 sidecar。

### 何时设计 pagecomponent

适合：

- 标准页面布局无法满足的复杂交互。
- 还款计划生成、复杂查询、批量选择、确认弹窗、外部系统信息展示。
- 需要前端聚合多个对象或接口结果。

### 何时设计 sidecar

适合：

- 回调接收。
- 外部系统 token 管理。
- 定时拉取外部数据。
- 队列、重试、幂等和监控。
- 多系统长链路编排。

## 反模式

- 没有扫描目标租户标准应用、标准对象和标准字段，就直接新建自定义对象。
- 已有客户小组、CPQ、服务工单、伙伴云等标准能力，却用自定义对象重建一套同义能力。
- 只写“新增对象”，不定义状态机和生命周期。
- 只写“同步外部系统”，不定义数据流向和失败处理。
- 用触发器直接调用慢接口。
- 没有记录类型，却用大量字段控制互斥页面。
- 没有相关列表，导致明细不可查询、不可报表、不可追踪。
- 没有权限和共享设计，后期才补数据可见性。
